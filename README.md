# Partly — поиск автозапчастей

React-приложение для поиска производителей по артикулу и просмотра аналогов и предложений выбранного производителя. Тестовое задание с локальным Mock API и русским интерфейсом.

## Функциональность

- Поиск производителей по артикулу и выбор производителя.
- Получение аналогов и предложений после выбора.
- Адаптивная таблица с артикулом, названием, производителем, ценой, валютой и остатком, включая нулевой.
- Состояния загрузки, ошибок и отсутствия результатов; повторный запрос предложений при ошибке.
- Debounce 450 мс, отмена устаревших запросов и защита от запоздавших ответов.
- Сброс зависимых результатов при изменении артикула или производителя.

## Технологии

React, JavaScript, Redux Toolkit, React Redux, Vite, Bootstrap 5, Vitest,
React Testing Library и ESLint. Тесты выполняются в jsdom.

## Запуск проекта

Требуются **Node.js 24.x** и **npm 11+**. Версия Node указана в `.nvmrc`,
для mise закреплена 24.22.2 в `mise.toml`.

```sh
npm ci
npm run dev
```

Откройте локальный адрес, который выведет Vite.

```sh
npm run verify   # ESLint, тесты и production build
npm run build    # отдельная сборка в dist/
npm run preview  # локальный просмотр собранного приложения
```

Для разработки тестов: `npm run test:watch`; однократный запуск: `npm test`.

## Примеры поиска

Введите артикул, дождитесь списка и выберите производителя:

| Артикул | Деталь | Доступные производители |
| --- | --- | --- |
| `OC384` | Масляный фильтр | MAHLE, MANN-FILTER |
| `0986AF1234` | Воздушный фильтр | BOSCH, MAHLE |
| `C27009` | Воздушный фильтр | MANN-FILTER, BOSCH |

У каждой пары артикула и производителя есть два предложения. Регистр и пробелы
по краям не влияют на поиск. Неизвестный артикул возвращает пустой результат;
`NETWORK_ERROR` позволяет проверить ошибку поиска производителей.

## Архитектура

- `src/App.jsx`, `src/features/parts/*.jsx` — интерфейс и взаимодействие с пользователем. Редактируемый текст и счётчик повторной попытки хранятся локально.
- `src/app/store.js`, `src/features/parts/partsSlice.js` — общий Redux store, выбранные значения, результаты, статусы, ошибки, селекторы и async thunks.
- `src/services/mockApi.js` — асинхронный сервис: нормализация входных данных, задержка, ответы, ошибки и отмена.
- `src/services/mockFixtures.js` — каталог демонстрационных данных; компоненты не обращаются к нему напрямую.
- `src/**/*.test.{js,jsx}`, `src/test/setup.js` — тесты сервиса, Redux и интерфейса, общая настройка окружения.

`createAsyncThunk` координирует запросы и их жизненный цикл. React-эффекты
отменяют устаревшие dispatch-промисы через `abort()`; внутренний `AbortController`
передаёт отмену через `thunkAPI.signal` в Mock API. Сервис удаляет таймеры и
обработчики сигнала. Редьюсеры дополнительно проверяют `requestId` и текущие
артикул/производителя, чтобы запоздавшие ответы и ошибки не изменяли актуальное
состояние. Отмена не показывается как ошибка.

Debounce откладывает поиск производителей на 450 мс после последнего изменения
нормализованного артикула. Зависимые результаты сбрасываются сразу при изменении
входных данных. Подробности: [архитектура](docs/architecture.md) и
[контракт Mock API](docs/api-contract.md).

## Mock API

Приложение использует локальный асинхронный моковый сервис с задержкой 500 мс.
Реальные HTTP-запросы не отправляются; сервер и API-ключи не нужны.
Цены, остатки, предложения и соответствия аналогов демонстрационные.
Совместимость деталей не проверена; данные не предназначены для покупки или подбора.

## Тестирование

Vitest и React Testing Library проверяют полный пользовательский сценарий,
нормализацию и пустой ввод, debounce, выбор и смену производителя, сброс результатов,
загрузку, отсутствие совпадений, ошибки и повторную загрузку предложений.
Проверяются отмена до и во время запроса, очистка ресурсов при размонтировании,
StrictMode, ответы и ошибки в произвольном порядке, а также независимость состояний
запросов. Тесты таблицы покрывают поля, форматирование валюты и нулевой остаток.
Таймеры и управляемые промисы делают асинхронные сценарии детерминированными.

Проверки DOM-семантики и фокуса в jsdom не заменяют ручную проверку адаптивной
вёрстки, клавиатурной навигации и экранного диктора в браузере.

## CI

`.github/workflows/ci.yml` запускается при push в `main` и pull request в `main`.
На Ubuntu устанавливается Node.js 24, кэшируется npm-кэш по `package-lock.json`,
затем выполняются `npm ci` и `npm run verify`. Доступ к репозиторию только на чтение;
дополнительные секреты и внешние API-ключи не требуются. Автоматического деплоя нет.
